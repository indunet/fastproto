2:T348e,<h1>Annotation Mapping</h1>
<p>A practical guide to map binary data to Java fields using FastProto annotations.</p>
<h2>Overview</h2>
<p>FastProto uses annotations placed on fields to describe how bytes map to values. During decode/encode, these annotations drive the binary-to-object conversion.</p>
<h2>Quick Mapping Steps</h2>
<ol>
<li>Identify each field’s byte offset (and bit offset if needed).</li>
<li>Pick the proper data type annotation (e.g., <code>@UInt16Type</code>).</li>
<li>Specify endianness only when it deviates from your class/global default.</li>
<li>For strings/arrays, specify <code>length</code>.</li>
<li>Validate no overlaps and that total length matches the buffer size.</li>
</ol>
<h2>Core Concepts</h2>
<ul>
<li><strong>Offsets</strong>: <code>offset</code> is the start byte index (0‑based). Bit fields use <code>byteOffset</code> + <code>bitOffset</code>.</li>
<li><strong>Byte/Bit Order</strong>: Use <code>@DefaultByteOrder</code> / <code>@DefaultBitOrder</code> at class level; override per field only when necessary. See <a href="/help/byte-and-bit-order">Byte &#x26; Bit Order</a>.</li>
<li><strong>Lengths</strong>: Strings and arrays require an explicit <code>length</code> (fixed-length mapping).</li>
</ul>

<h2>Advanced: Reverse Addressing</h2>
<ul>
<li>Encode to a fixed-length buffer via <code>FastProto.encode(obj, length)</code> so fields near the end can be addressed safely.</li>
</ul>
<h2>Best Practices</h2>
<ul>
<li>Keep offsets aligned and avoid overlaps; leave explicit gaps with comments when reserving bytes.</li>
<li>Prefer class-level defaults for byte/bit order, override only when needed. See <a href="/help/byte-and-bit-order">Byte &#x26; Bit Order</a>.</li>
<li>For checksums, use a single <code>@Checksum</code> (start/length/offset). See <a href="/help/checksum">Checksum/CRC</a>.</li>
<li>For magic bytes and fixed version fields, prefer <code>@Expect</code>. See <a href="/help/expect">Expect Assertions</a>.</li>
