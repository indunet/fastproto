2:T35f8,<h2>Variable Length and Struct Arrays</h2>
<h3>Overview</h3>
<p>Variable-length fields are common in binary protocols. FastProto supports them via the <code>lengthRef</code> attribute on many annotations, allowing a field to reference a length/count defined elsewhere in the same class. This works for strings, byte arrays, numeric arrays, boolean arrays, and struct arrays.</p>
<ul>
<li>Supported annotations (selected): <code>StringType</code>, <code>BinaryType</code>, <code>AsciiArrayType</code>, <code>CharArrayType</code>, <code>BoolArrayType</code>, <code>Int8ArrayType</code>, <code>Int16ArrayType</code>, <code>Int32ArrayType</code>, <code>Int64ArrayType</code>, <code>UInt8ArrayType</code>, <code>UInt16ArrayType</code>, <code>UInt32ArrayType</code>, <code>UInt64ArrayType</code>, <code>FloatArrayType</code>, <code>DoubleArrayType</code>, <code>StructArrayType</code>.</li>
<li><code>@AutoType</code> also supports <code>lengthRef</code> so you can write <code>@AutoType(offset=..., lengthRef="$count")</code> for arrays/strings/collections.</li>
</ul>
<h3>Basics: length vs lengthRef</h3>
<ul>
<li><code>length</code>: a fixed number of elements/bytes.</li>
<li><code>lengthRef</code>: the name of a field in the same class that holds the length/count; it <strong>must</strong> be prefixed with <code>$</code> (e.g. <code>$count</code>).</li>
<li>If both are set, <code>lengthRef</code> takes precedence for the effective length.</li>
</ul>

<h3>Tips and caveats</h3>
<ul>
<li>Ensure the referenced length field is decoded before the variable-length field (i.e., it appears earlier in the class with a lower offset).</li>
<li><code>lengthRef</code> is case-sensitive and must start with <code>$</code> followed by the field name.</li>
<li>For strings, you can also set <code>charset</code>.</li>
<li>For boolean bit arrays, use <code>BoolArrayType</code> (byte-aligned). Per-bit packed variable-length booleans are not supported.</li>
<li>With <code>@AutoType</code>, you must still supply <code>offset</code> and <code>lengthRef</code> for arrays/strings; FastProto infers only the data type, not the layout.</li>
</ul>
