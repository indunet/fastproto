2:T33fa,<h1>Arrays &#x26; Strings</h1>
<p>A focused guide on mapping strings and arrays: how <code>offset</code> and <code>length</code> work, element endianness, and common pitfalls.</p>
<h2>Overview</h2>
<p>Strings and arrays are fixed-length in FastProto. You declare the starting byte offset and an explicit length (in bytes for strings, in elements for arrays). During encode/decode, FastProto reads/writes exactly that span.</p>
<h2>Quick Steps</h2>
<ol>
<li>Decide the start byte <code>offset</code> for the field.</li>
<li>For strings, specify <code>length</code> (bytes). For arrays, specify <code>length</code> (elements).</li>
<li>If numeric array elements need a specific endianness, set <code>byteOrder</code> on the array annotation.</li>
<li>Verify the declared region fits entirely in your buffer.</li>
</ol>
<h2>Core Concepts</h2>
<ul>
<li><strong>Fixed length</strong>: Strings/arrays are not auto‑sized; the declared <code>length</code> is authoritative.</li>
<li><strong>Padding/Truncation</strong>: Producers should zero‑pad unused bytes in strings. On encode, longer content than <code>length</code> will be truncated to fit.</li>
<li><strong>Encoding</strong>: Choose a consistent character encoding at the system boundary (e.g., ASCII/UTF‑8) and ensure both sides agree.</li>
<li><strong>Element endianness</strong>: For numeric arrays, <code>byteOrder</code> applies per element.</li>
</ul>

<h2>Advanced</h2>
<ul>
<li><strong>Variable‑length data</strong>: If your protocol uses dynamic lengths, carry the size in another field and compute buffer layout in your application before calling <code>encode(object, totalLength)</code>. Arrays/strings still need a concrete <code>length</code> at mapping time.</li>
<li><strong>Reverse addressing</strong>: For layouts that reference the tail, use fixed total length (<code>FastProto.encode(obj, length)</code>) so trailing regions can be addressed safely.</li>
</ul>
<h2>Best Practices &#x26; Pitfalls</h2>
<ul>
<li>Ensure declared regions do not overlap and fit within the buffer.</li>
<li>Align offsets deliberately; leave commented gaps for reserved bytes.</li>
<li>Keep encoding consistent across systems; avoid mixing encodings.</li>
<li>For numeric arrays, always specify <code>byteOrder</code> explicitly if your spec requires it.</li>
