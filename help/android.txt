1c:T2b3f,<h2>Android Compatibility Guide</h2>
<p>This page summarizes how to use FastProto on Android.</p>
<h2>What Works</h2>
<ul>
<li>Annotation-based mapping for primitive types, arrays, strings, enums, bit/byte order, and checksum/CRC</li>
<li>Decode/encode via <code>FastProto.decode(...)</code> and <code>FastProto.encode(...)</code></li>
<li>Builder/Utils APIs (no annotations)</li>
<li><strong>Lambda formulas with annotation processor</strong> (since 4.0.0)</li>
</ul>
<h2>Lambda Formulas on Android</h2>
<p>FastProto provides compile-time support for lambda formulas so <code>@DecodingFormula(lambda = "...")</code> and <code>@EncodingFormula(lambda = "...")</code> remain Android-friendly.</p>
<h3>Setup</h3>
<p>Android projects can use the <code>fastproto</code> dependency directly. If you use lambda formulas, make sure annotation processing is enabled in your build.</p>

<h3>How It Works</h3>
<p>The annotation processor scans your code at compile time and generates <code>Function</code> implementation classes for each lambda expression. These generated classes are included in your APK and used at runtime instead of dynamic compilation.</p>

<h2>Current Limitations</h2>
<ul>
<li><code>java.sql.Timestamp</code> is not part of Android standard APIs
<ul>
<li>Impact: Types/codec relying on <code>java.sql.*</code> will not work. Prefer <code>long</code> epoch millis or <code>java.time.*</code> (with desugaring) instead.</li>
</ul>
</li>
</ul>
<h2>Other Android Setup</h2>
<ul>
<li><strong>Time Types</strong>
<ul>
<li>Prefer <code>long</code> (epoch millis) or <code>java.time.Instant/LocalDateTime</code>.</li>
<li>Enable core library desugaring to use <code>java.time.*</code> on older Android.</li>
</ul>
</li>
<li><strong>Gradle Setup (library/app module)</strong>
<ul>
<li>compileOptions.sourceCompatibility/targetCompatibility = 1.8</li>
<li>coreLibraryDesugaringEnabled = true</li>
<li>Add dependency: <code>com.android.tools:desugar_jdk_libs</code></li>
</ul>
</li>

<ul>
<li>Keep runtime annotations and members used by reflection</li>

</ul>
</li>

<h2>FAQ</h2>
<ul>
<li><strong>Can I use lambda formulas on Android?</strong> Yes. Lambda formulas are generated at compile time, so they are compatible with Android as long as annotation processing is enabled.</li>
<li><strong>Do I need the annotation processor?</strong> If you use <code>@DecodingFormula(lambda = "...")</code> or <code>@EncodingFormula(lambda = "...")</code>, yes. If you only use class-based formulas like <code>@DecodingFormula(MyFormula.class)</code>, the annotation processor is optional.</li>
<li><strong>Do I need ProGuard rules?</strong> If you rely on reflection/annotations, keep them as shown above. The generated formula classes should also be kept.</li>
